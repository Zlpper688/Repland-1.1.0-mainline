日期：2026-11-15 ｜ 语料：`dev/matter-lab/cold-corpus.mjs`（K001–K090）
线上 AI：生产 `/api/assistant`，一次性访客账号，25 条/账号，每条前重置并注入上下文
规则层：`functions/rule-parser.mjs`（与生产同一份）｜ 复算：`dev/matter-lab/cold-reeval.mjs`

## 结论

| 路线 | 正确 | 危险写入 | 说明 |
| --- | --- | --- | --- |
| 规则单跑 | 87/90 = 96.7% | 0 | 覆盖 82.2%，覆盖内正确率 100% |

## 规则护栏在冷启动里实际做了什么（90 条）

- `floor` 13：AI 返回空/仅追问，但句子有安全规则读法，用规则执行
- `move` 7：AI 把「改到/挪到」读成新建或读错日子，规则改回移动
- `postpone` 2：AI 用 schedule 代替 postpone（会留旧块），规则改成顺延语义
- `review` 7：「没背完/没练完，后天补四十分钟」AI 只排新增，规则补上未完成 + 保留原块

## AI 单跑的失败类型（单次采样，仅作边界证据）

1. 丢日期：K022「周三交课程论文」、K023「明天交英语作业」、K028「周四交课程设计」→ 存成无日期待办
2. 截止误读：K008/K013/K074/K075 把「X 点前交」当成日程块或丢掉截止时刻
3. 移动读错：K029「明早的跑步挪到傍晚六点」→ 排到了今天
4. 状态动作错：K039–K048 完成/取消/进度经常不识别；K045/K046 用 schedule 代替 postpone
5. 复盘协议：K051–K060 只排新增、不确认未完成，或把补时读成移动
6. 多意图退化：K088 返回一段分析文字、无 items

以上 1–5 全部由规则层修复；第 6 类没有安全执行，按设计降级为追问。

## 评测口径的两处修正（不是放宽执行门槛）

- query/clarify 都是「不写状态」的回答：只要没有 items 且有实质回复，按行为正确计，同时记录标签不一致（K081/K082 属于此类）。
- K086「tomorrow 3pm meeting」改为 `allowAsk`：AI 正确执行算对，离线规则安全追问也算对——这条正是「规则是地板、AI 是上限」的样本。

## 剩余缺口

- K088 多意图仍依赖模型：规则必须硬转交（`mustAsk: multi-intent`），AI 这次输出退化后用户得到的是追问而非静默执行。下一步应改提示词/换模型验证多意图拆分，不给规则加场景补丁。
- 线上 AI 为单次采样，数字有波动；每次改规则后都应重跑 `cold-rule`、`port-check`、`test:routes`。
- `out/cold-ai.jsonl` 里的 `hybrid` 字段由旧映射（只读 `startMinute`）生成，已被 `cold-reeval` 的复算结果取代；统计只看 `cold-ai-reeval.json`。

## 复现

```bash
node dev/matter-lab/cold-rule.mjs      # 规则单跑
node dev/matter-lab/cold-live.mjs      # 线上 AI（消耗访客额度，约 8 分钟）
node dev/matter-lab/cold-reeval.mjs    # 用已存预测复算混合
node dev/matter-lab/port-check.mjs     # 500 条训练集回归
npm run test:routes                    # 生产路由回归
```
