# REPLAND 团队协作模块设计（v2 · 定稿）

> 2026-10-28 落盘。基于七轮需求对齐（52 问全部锁定）+ 全量代码调研（`D:\repland-build` v0.1.35+，`2f1b76c`）。
> 本文档是唯一权威设计；旧版设计文档（WorkBuddy AI 快照内）已废弃删除。

---

## 1. 定位与价值主张

**面向高校竞赛团队的常驻式 AI 协同调度与贡献留痕账本。**

- AI 不替团队定大方向；**队长锁定项目基线**（顶层硬约束），AI 只承接基线内高频、细碎、反复的调度变更
- 砍掉队长反复核对、同步、重排、汇总的调度负担；队长约等于只与 AI 对接
- 贡献**只客观留证，不打分不排名**；台账是答辩素材和信任基础
- 个人规划（现有四 tab 闭环）完全不动；团队模块是叠加在其上的新组成部分

## 2. 双层调度模型

| 层 | 载体 | 谁定 | 内容 |
|---|---|---|---|
| 硬约束层 | 甘特图 | 队长锁定 | 比赛截止 > 里程碑 > 依赖 > 基线任务包 |
| 软调度层 | 晾衣绳时间线 | AI 常驻托管 + 队员可改 | 中期/短期任务卡片，卡片大小 = 预计工时 |

- 晾衣绳时间轴**只有日/月两档**（比赛周期就这么长），两档各有卡片显示方案；阶段作为轴上分区色带
- 可拖动浏览整个时间线；拖动 = 调整预期并触发重排预告
- 「未来时间预期」独立功能暂不做——其本质（过去→档案、未来计划全员可见）由时间线自然承载

## 3. 比赛档案卡（二级卡片机制）

### 3.1 一级卡：比赛参数卡

AI 收到比赛材料（文件/图片/文字）后**整体文字梳理** → 能结构化的写入参数卡（成为基线硬约束参数）→ 不能结构化的写入底部**补充区**。

**预设槽位六组**（调研 10 类赛事规程归纳：互联网+ / 挑战杯 / 大创 / 数模 / 电赛 / 蓝桥杯 / ICPC-CCPC / RoboMaster / 4C / NECCS / 市调）：

1. **基本信息**：全称/简称、主办方、级别（枚举：国际/国家/省/校）、赛道·组别·赛题、官方文件附件
2. **时间节点**：报名截止、初赛/省赛、提交截止、决赛/国赛、各节点提醒开关
3. **组队与资格**：人数上下限、指导教师上限、学历/年级限制、每校/每人限报规则、队员与分工
4. **提交物**：清单（类型+截止+负责人）、需查重+阈值、专利/软著佐证
5. **评审与规则**：晋级路径、评审要点、现场答辩要求
6. **资源与其他**：报名费/预算、场地器件、特殊流程

- **留空隐藏**：AI 未提取的槽位标 `unknown` 折叠不渲染；用到再显示；关键槽位（报名截止、人数上限）缺失显示「待补充」引导
- **补充区**：预设外关键信息存键值对（数模赛题号 A-F、电赛器件清单、RM 机器人配额、4C 决赛区城市等单一赛事特有参数）
- **升级机制**：同一键名在 ≥3 张卡出现，或用户手动「升级为槽位」→ 转正式槽位并回填存量卡

### 3.2 二级卡：队员卡

- **负责说明（项目维度）**：本项目里每人管什么；换项目就换；队长和本人都可改、双向可见；单项目内公开
- **画像（人维度）**：跨项目固有的长期记忆（§12），与负责说明严格分离
- AI 排任务一部分依据负责说明（作为适配权重输入），画像提供跨项目佐证

## 4. 任务体系

- **长期任务 = 竞赛本身**（不管几天）；**中期任务 = 挂阶段**（项目书/制作/PPT 等，必须在所属阶段截止前完成）；**短期任务 = 会议类**
- **期限 = f(类型, 阶段截止, 依赖位置)**：下游依赖 → 上游自动提早（上游截止 = 下游开工 − 下游剩余时长 − 缓冲，系统自动算并联动，队长甘特可调）；依赖边在队长建基线时设定
- **阶段**：队长自定义（数量+名称+起止日期），也可套用环节模板（数模赛 / 创新类 / 通用三阶段）：一次生成连续阶段窗口、交付物、检查点与基线任务，生成后仍逐项可改
- **关键时点**：阶段内除交付物/检查点外，还带日期化的关键时点（报名截止、定题、初稿齐、提交、答辩）；`hard = true` 的时点错过就回不来，随阶段一起持久化
- **关卡**：提交、答辩等 `isGate` 环节要等前面所有环节交付才真正过关；就绪度按「剩下多少活 vs 窗口里还剩多少容量」判定（已收尾 / 来得及 / 有风险 / 未就绪），只提示不替队长砍范围
- **拆解流**：队长建阶段任务 → AI 按负责说明+画像拆子任务草案 → 队长审改 → 走确认流分配；队员可领未分配子任务
- **卡片大小**：AI 按描述估工时，队长可调；宽度 = 预计工时，实测以执行块累计修正
- **模板套用是部分成功**：重复编号、倒挂日期、悬空阶段逐条跳过并在一条通知里汇报，整批不回滚（能用的先用上）

## 5. 调度内核（确定性）

**LLM 只做文秘（口语解析/摘要/提取），重排是内定固定流程。**

- 初始化输入：队伍组成 + 成员负责说明 + 任务定位
- 运行时：算剩余工作量 → 看负载与适配 → 决策延后本人 vs 转派他人 → 依赖联动 → 自动通知
- **安排 = 负载定谁 + 某天空闲定排哪段**：排进某人的某天时段，同时队员可以修改（改自己的时间/时长，在自己的空闲内；跨人转派仍走转派+一键异议）
- **个人日程是唯一真相源**：所有队伍的安排都落到同一份个人日程；跨队冲突按优先级+先到先得，冲突块标红由本人裁决
- 今天已经过去的时段不排：当天从下一个半小时边界起步，草案不会把活放到上午而实际生成于深夜
- 会议排期看全员空闲交集：给日期就列当天候选；不给日期就按接受度给未来一周推荐——每天取最宽的两段，下午 14–18 优先，其次上午 9–12、晚上 18–21，午饭和深夜降权
- 课表不当团队调度的刚性约束；成员没导入课表 → 照排但标低置信度（保守排大段空闲），补完自动重排该成员任务
- **修复优先于拒绝**：依赖成环时忽略环内依赖、先排无环部分，并给出 ERROR 诊断；未排上的任务都带「为什么 + 建议怎么办」
- **统一诊断层** `TeamDiagnostics`：severity / 对象 / code / advice，助手、UI、周报共用同一份结构；notes 只是它的句子里层

## 6. Agent 层设计（复用 `domain/planteam` runtime）

个人六席（REQUIREMENTS/CALIBRATOR/AVAILABILITY/HABIT/CONFLICT/COMPOSER）不动，**新增团队三席**，同一 `AgentRegistry` 注册：

| 角色 | 职责 |
|---|---|
| `SCHEDULER` 排期官 | 负载定人+空闲定时段+依赖倒算 → 分配草案 |
| `LIAISON` 对接官 | 队员原话 → 结构化请求 → 触发重排 → 通知 |
| `LEDGER` 台账官 | 执行块/状态流转/外链/财务流水 → 贡献证据 → 周报草稿 |

- **团队 workspace 槽位**：`TEAM_BRIEF`（档案卡+基线）/ `ROSTER`（成员+负责说明+画像）/ `LOAD_SNAPSHOT`（负载与空闲）/ `TEAM_DRAFT`（分配草案）/ `EXCEPTIONS`（异常区）/ `LEDGER_SNAP`（台账快照）
- **工具**：`REQ_AI`（口语解析/档案卡提取，走 BYOK）、`MEM_WRITE`（记忆库写入，权限门控）、`CAL_CONFLICT`（硬约束校验，确定性）
- **两级验收**：一级 = 截止/依赖/容量硬约束；二级 = 权限与可见性（越权请求直接 FAIL）
- **数据流**：队员说事 → LIAISON → SCHEDULER → TEAM_DRAFT → 队长确认或自动生效+一键异议 → 落库+通知

## 7. 对接流与信息架构（队长端唯一界面）

- **信息单点归属**：任务的重排/转派/原话长在任务卡上，不重复出现在别处
- **AI 默认不写句子**：AI 只产结构信息；有话是队员原话原样上浮；AI 理由全收进「详情」
- **确认面板 = 对象上的结构化操作**，非方案套餐：
  - **截止日期设定**：时间轮盘（月/日/时三列滚轮），选中即 AI 倒排（显示剩几天、每日排多少小时）；超过比赛截止标红拦截；AI 建议值做成胶囊一键跳转
  - **取消**（内化 MoSCoW）：建基线时任务定级（任务属性）；取消 = 把 Should/Could 降为 Won't（划线+可撤销），Must 不可取消
  - **接手人**：推荐按钮（名字+推荐度）+ 按推荐度排序的下拉
- 转派自动生效 + 被转派人一键异议；基线责任（台账）与执行流转分离，双线留痕

## 8. 可见性模型

- 课表默认共享；个人任务默认私有需标记公开；私有时间 = 「在忙」斜纹占位块（时间可见，内容任何人含队长不可见）
- 周报**不对个人作评价，只写项目进展**（守「留证不留评」）
- 权限控制台只管功能开关；数据可见性按既有模型，不做按人配置

## 9. 贡献台账

- **基线任务 + 增量任务**双层；只客观留证：时间/产出/外链
- **轻记录不是功能，是项目自觉**：不设专门登记模块，进度由各模块高内聚自然沉淀（执行块、任务状态流转、外链、会议出席自动记录）
- 给不擅长记录的人：口语登记为主（对 AI 说「这周调研做完了」→ 解析成台账条目）+ 极简滑动登记兜底（自动带时间戳）
- **财务记账**：独立小模块，流水全队可查（报销透明是竞赛刚需），录入限「财务记账」权限授权成员

## 10. 权限控制台

- 现实：很多队伍不止队长在安排（技术负责等同样重要）
- **队长默认全权限；队员权限由队长按人在控制台配置**；「技术负责/财务/文案」等头衔只是标签不自带权限
- 权限项：改基线与截止 / 排期与转派 / 创建任务 / 邀请移除成员 / 发起会议排期 / 台账编辑 / **财务记账** / **记忆库写入** / **晾衣架内容整理** / 周报开关 / 文件外链管理 / 解散归档

## 11. 周报

- **开关制**：开启后哪怕零记录，系统也根据一周表现数据自动总结项目进展
- 表现数据 = 执行块完成情况 + 任务状态流转 + 台账条目 + 会议出席（只用团队维度数据 + 本人授权的个人日程块）
- 结构：进展摘要 / 风险雷达 / 下周重点 / 客观留证数据；全队可见，没人需要写

## 12. 记忆体系

- 现有框架（FSRS 形状记忆 + `AgentMemoryBank` per-agent 24 事实/6 episode + `AuxiliaryStore`）是底座
- 扩展两个域，**严格区分团队与个人**：
  - `HumanProfileMemory`（个人域）：跨项目画像，只有本人可见，跟随账号
  - `TeamMemory`（团队域）：档案卡/负责说明/会议结论，全队可读；写入受「记忆库写入」权限门控
- **mem0 后置**：作为可选远端同步层接入（服务端持有），不改变客户端离线优先
- **比赛归档**：一键归档「参赛档案」（成绩+最终台账+作品外链）进个人记忆域沉淀，可导出；队伍转只读

## 13. 账号、后端与飞书

- **账号**：手机号验证码 + 微信登录双通道（国内高校最通用）
- **后端**：自托管 Postgres + Ktor（Kotlin 同栈）；表级增量拉取同步，本地 Room 仍是主副本；`external_links`/`sync_outbox` 扩展表沿用既有探索设计
- **实时性**：推送通知 + 拉取起步（全周期竞赛辅助对即时交互需求低），留 WebSocket 接口后置
- **凭证哲学（BYOK 延伸）**：后端凭证、飞书 app_id/app_secret 全部服务端持有，App 只配「后端地址 + 账号 token」；飞书应用由队长自建（个人团队可建自建应用，免企业认证、免审发布）
- **飞书接入**：后端直调 REST + 长连接 WebSocket 事件订阅（Java SDK，免公网回调）；**MCP 不作基础层**（官方 lark-openapi-mcp 是 AI Agent 工具层，不支持文档编辑/文件上传，对确定性调用链是纯开销）——留作未来 AI 助手增强层
- **第一波范围**：消息通知 + 会议写入飞书日历 + 外链文档绑定；任务/多维表格同步后置

## 14. 工程落点与纪律

- **主仓库 `D:\repland-build` 开新分支**，新增 `domain/team/` + `ui/team/`；不再独立仓库（上次跨仓库整合成本过高）
- **UI**：`TEAM` tab 接入现有 `AppTab`/底部导航体系（`AGENT` tab 已标记迁移/隐藏，位置让给 TEAM）
- **构建边界**：照搬 `src/remote` sourceSet + 反射加载模式——团队联网能力（后端/飞书）只在 debug/internal 构建，release 沿用离线边界；`verifyOfflineMvpBoundary` 改分级守卫（个人域保持离线断言，team 域显式放行）
- **纪律沿用**：AI 请求不直接写仓库、确认幂等、来源版本检查、变更走草案→确认

## 15. 降级矩阵（BYOK 未配 key 时）

| 能力 | 可用性 |
|---|---|
| 确定性排期/负载/依赖/台账/会议候选 | ✅ 全量本地可用 |
| 口语解析、档案卡提取、周报 LLM 摘要 | ⬇ 降级为结构化表单手动填 |

**「没有 AI 也能用，配了 AI 更省力。」** 未配 key 不禁止进团队模块。

## 16. 建队与生命周期

- **建队**：队长设基线（上传比赛材料 → 档案卡）→ 加队员：账号搜索（手机号）+ 邀请码双通道，队员确认进队 → 入队建「负责说明」空卡引导填写
- **退队**：名下任务自动转派（走异议机制）+ 台账永久留痕不删
- **多队**：一账号可建多队伍，**一队伍绑定一个比赛基线**；跨队共享个人画像但基线隔离
- **结束**：一键归档参赛档案 → 队伍只读
- **通知分级**：需要行动的（待确认/异议/会议临近）→ App 推送+飞书双通道；纯状态变更 → 仅 App 内

## 18. 竞品与差异化依据

- 飞书查忙 / Outlook 助理 / Carly（每人一行状态条+计数+Best times）：忙闲查询被证伪为伪需求 → 改任务维度安排状态
- WakeUp 课程表语言：课表共享的视觉与交互参照
- Google/Apple「+N more」折叠：日满载时的收纳参照
- pm-skills（phuryn）`prioritization-frameworks`：MoSCoW 内化为「取消」机制（分级是任务属性，操作是通用勾选）
- **差异化**：AI 只承接基线内调度而非替团队决策；确定性内核保证可解释；台账留证不留评；飞书不做协同文档（外链绑定）

### 18.1 REA 竞品扫描（2026-11，证据版）

> 原文与证据：`docs/COMPETITOR_SCAN.md`、`docs/research/competitor-2026-11/`。

- 采样：Motion / Reclaim / Sunsama / Teambition / 飞书项目 / 赛氪，公开首页与价格页，DOM + a11y + 截图三份证据。
- 采纳：风险提前说（结构化诊断）、变更后可重算、安全预览再批准、每日负载条、缓冲显性化、模板小而准。
- 拒绝：流程引擎、AI 笔记/文档、组织级人力分析、多视图、报名支付、AI 直接改计划。
- 结论：竞品在做「AI 替人决定」；我们补的是**可解释、可修复、可预览**的基础设施，决策权与证据仍在队长和队员手里。

## 19. 废弃思路清单（防回潮）

1. 泳道版团队视图（把个人日程细节当团队主体）
2. 6 视图 + 5 态图例的忙闲带（认知负担过大）
3. 「谁有空」独立查询功能（有空不重要，安排状态才重要）
4. 负载均衡作为卖点（降级为内核输入）
5. 顺延 = +N 天增量（改为截止日期设定 + AI 倒排）
6. 每任务自定义砍范围问卷（改为通用「取消」机制）
7. 协同文档（飞书/语雀外链绑定替代）

## 20. 答辩防御要点

- **为什么 AI 不替队长决策**：基线是责任边界，AI 越权决策等于队长失职自动化；锁基线才能保证可追责
- **为什么确定性内核 + LLM 文秘**：调度可解释、可复现、断网可用；LLM 只处理它擅长的语言模糊性
- **为什么留证不留评**：评分引发成员对立；客观留证服务答辩与复盘
- **为什么账号/后端现在做**：团队协作的多端本质需求，离线单机边界从「限制」转为「分级守卫」
- **和飞书有什么区别**：飞书是通用协作平台，本产品是「会排期的队长副驾驶」+ 贡献账本；通过飞书长连接集成而非重复造轮子
